# Contributing

Thanks for your interest. These are mostly personal repositories, so the process is light:

1. **Open an issue first** for anything beyond a typo, to agree on the change before you write it.
2. **Keep pull requests small**: one change per pull request, with a short description of the why.
3. **Follow the existing style** of the repository, and run its build or tests (see its README) before submitting.
4. **No secrets, no personal data** in issues, commits or pull requests.

Security problems are not reported in issues: see [SECURITY.md](SECURITY.md).

Everyone taking part follows the [code of conduct](CODE_OF_CONDUCT.md).
